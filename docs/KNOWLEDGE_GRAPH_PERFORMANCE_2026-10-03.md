# 지식 그래프 지연 개선 — 2026-10-03

## 원인과 변경

실제 LLM 검증에서 그래프 생성은 3–9ms, SHACL 검증은 163–509ms였습니다. 전체 479–871ms 중 나머지는 주로 Python 프로세스 시작·라이브러리 로딩과 저장에 사용됐습니다. 그래프 생성 자체보다 반복 초기화와 노드마다 고정 SPARQL 쿼리를 다시 파싱하는 비용이 컸습니다.

다음 세 가지를 변경했습니다.

1. 고정 SHACL-SPARQL 실행 계획을 최대 8개 캐시합니다. 그래프와 포커스 바인딩은 작업마다 새로 사용합니다. 온톨로지와 SHACL 파일, 검증 규칙은 그대로입니다.
2. 별도 관찰 프로세스를 재사용합니다. 작업은 슬롯별 순차 실행하며 API 프로세스마다 최대 1–2개입니다. 100개 작업 뒤에 교체하고, 실패·시간 초과·직접 관찰 취소 시에도 해당 프로세스를 폐기합니다.
3. `shadow` API는 작은 마스킹 레코드를 복사·제출한 뒤 응답을 반환합니다. 그래프 생성·검증·저장을 응답 경로에서 기다리지 않습니다. 정상 서버 종료는 제출한 작업을 마친 뒤 자식 프로세스를 종료합니다.

기존 입력·응답·프롬프트·모델 호출 절차는 변경하지 않았습니다. 처리 슬롯이 가득 차면 기존 정책대로 관찰 작업을 생략하며 대기열을 추가하지 않습니다.

## 같은 두 단계 입력의 처리 시간

macOS arm64 / Python 3.12.14에서 기존 실제 모델 응답과 온라인 `record.json.gz`를 재생했습니다. 로그·소스 두 단계를 모두 포함하고, 개선 전 코드를 별도 복사해 동일한 자료를 각 10회씩 순차 처리했습니다. **추가 모델 호출은 0회**입니다.

| 입력 | 개선 전 중앙값 | 개선 후 재사용 중앙값 | 개선 후 첫 실행 | 최종 트리플 |
|---|---:|---:|---:|---:|
| 빌드 타입 오류 | 672.2ms | 55.1ms | 391.1ms | 249 |
| 런타임 설정 키 오류 | 672.7ms | 58.8ms | 402.5ms | 281 |

재사용 작업의 처리 시간은 약 91–92% 감소했습니다. 첫 실행에는 여전히 초기화 비용이 있습니다. 각 개선 후 표본은 첫 작업 1개와 재사용 작업 9개이며, 표본 수가 작아 대규모 부하의 성능을 보장하지 않습니다. 개선 전·후 모두 각 입력 10/10건이 저장·SHACL 검증에 통과했고 그래프 트리플 수도 같았습니다.

## HTTP 응답 지연

저장된 실제 모델 답변을 테스트 런타임으로 재생하고, 같은 백엔드 합성 자료로 API를 `off`·`shadow` 각각 10회 호출했습니다. 모델과 S3 전송은 모의 처리했으며, 그래프 작업은 실제 코드를 실행했습니다. 응답을 받은 시점에 HTTP 시간을 기록하고, 다음 요청 전에 관찰 작업을 완료시켰습니다.

| 항목 | 중앙값 |
|---|---:|
| `off` HTTP 시간 | 15.27ms |
| `shadow` HTTP 시간 | 18.51ms |
| 관찰 사용에 따른 HTTP 시간 차이 | 약 3.24ms |
| 마스킹 레코드 복사·제출 시간 | 2.19ms |

이는 짧은 로컬 ASGI 재생 측정입니다. 실제 인터넷 요청·모델 응답 시간이나 운영 환경의 동시 부하를 측정한 값은 아닙니다. 작업 완료를 기다리는 `benchmark_knowledge.py`의 그래프 시간과 HTTP 추가 지연을 구분해야 합니다.

## 검증과 운영 조건

- 전체 테스트 298개, Ruff 및 diff 공백 검사 통과
- 고정 쿼리 캐시와 일반 RDFLib 처리의 검증 결과 일치
- 차단된 그래프 작업이 있어도 API 응답 반환, 정상 종료 시 작업 완료·프로세스 종료
- 제출 뒤 원본 객체 변경에도 저장 스냅샷 유지
- 프로세스 재사용·100개 작업 후 교체·시간 초과 후 다음 작업 복구
- 실행 전 작업 취소와 실행 중 취소의 슬롯·프로세스 정리
- 기존 응답·모델 입력 동일성 및 이전 오류·마스킹·범위 검사 유지
- 최종 Docker 이미지에서 비루트 사용자로 실제 프로세스 재사용, SHACL 통과, 디렉터리·파일 권한, 종료 처리 확인

재사용 프로세스는 유휴 상태에도 이번 로컬 표본 기준 약 56MiB의 메모리를 유지합니다. 초기화 시간을 줄이는 대신 서버 종료까지 메모리가 유지되는 구조입니다. 실제 메모리 최대치는 입력·동시 슬롯·배포 환경에 따라 달라집니다.

`submitted`는 관찰 작업 제출이며 저장 완료가 아닙니다. 저장 완료는 `recorded`와 산출물로 확인합니다. 정상 종료에서는 작업 제한 시간을 적용하여 마무리하지만, 강제 종료 시 제출한 작업이 유실될 수 있습니다. 영속 작업 큐와 저장 보장은 아직 이번 관찰 경로에 포함하지 않았습니다.

성능 표본은 `results/graph-performance-before-*`, `results/graph-performance-after-*`, `results/api-graph-latency`에 보관합니다. 재현 명령에는 같은 진단의 두 파일을 전달합니다.

```bash
.venv/bin/python evaluation/benchmark_knowledge.py --input results/backend-llm-shadow-20261003/compile-source.json --stage-record results/backend-llm-shadow-20261003/knowledge/<해당-진단-디렉터리>/record.json.gz --output-dir results/new-performance --runs 10
```

실행·설정은 [지식 그래프 개발 문서](KNOWLEDGE_GRAPH_SHADOW.md), 처음의 실제 모델 호출 결과는 [LLM 검증 보고서](LIVE_LLM_SHADOW_TEST_REPORT_2026-10-03.md)를 참고하세요.

# 온톨로지 이전 구조와 현재 구조 비교 — 2026-10-03

현재 `shadow` 구조는 기존 진단 뒤에 그래프 관찰을 추가합니다. **LLM에 전달하는 자료·프롬프트·스키마가 같으며, 그래프가 진단을 선택하거나 수정하지 않습니다.** 따라서 현재 변경으로 진단 정확도가 높아졌다고 주장할 근거는 없습니다.

## 같은 답변을 사용한 비교 결과

실제 LLM 평가에서 저장한 20개 입력과 답변을 온톨로지 이전 Git 커밋 `40d39767fcd209c24e84dd88aebeb9979d0a6e9b` 및 현재 코드에 재생했습니다. 이전 소스는 해당 커밋의 `src`를 별도 디렉터리에 추출하고, 다른 Python 프로세스에서 실행했습니다. 각 실행의 API 모듈 경로를 확인하여 이전 실행에 현재 소스가 섞이지 않았음을 검사했습니다.

두 실행의 모델 프롬프트·입력·응답 스키마 해시는 사례 20/20에서 일치했고, 단계 제출 수 역시 20/20에서 일치했습니다. 진단 ID와 실행 메타데이터를 제외한 공개 결과도 20/20에서 같았으며 OpenAPI도 동일했습니다. 두 실행의 모든 정확도 지표는 앞선 실제 LLM 평가의 지표와 같습니다.

**이 표는 독립적으로 모델을 다시 호출한 A/B 정확도 실험이 아닙니다.** 동일한 실제 모델 답변을 재생하여 진단 경로와 계약의 동일성을 검사한 결과입니다. 추가 제공자 호출은 0회입니다. 첫 단계 소스 조회 응답은 저장된 단계 분석과 공개 결과의 조회 이유·파일 범위로 복원했으므로 원래 제공자가 반환한 원문 전체를 그대로 재생한 것도 아닙니다. 복원한 동일 응답을 양쪽에 사용했고, 양쪽이 모델에 전달한 자료의 일치를 별도로 확인했습니다.

원인 식별률은 사전 정규식 채점 기준입니다. 미통과 1건은 마이그레이션의 원인 표현 검사이며, 코드 위치 미연결 1건은 로그만으로 충분한 PORT 설정 오류에서 소스 조회를 생략한 경우입니다. 상세 해석과 합성 평가 한계는 [합성 장애 평가 보고서](SYNTHETIC_DIAGNOSIS_EVALUATION_2026-10-03.md)에 기록했습니다.

## 구조와 비용의 차이

이전 구조도 로그 EV ID와 코드 SC ID를 연결하고 JSON 규격·참조·파일과 줄을 검사했습니다. 현재는 그 연결을 분석 단계·배포 시도와 함께 RDF로 보관하고 SHACL로 추가 검사합니다. 원인 후보는 계속 `unverified`이며, SHACL 적합은 원인의 사실 여부를 증명하지 않습니다.

| 항목 | 이전 | 현재 |
|---|---|---|
| 진단 흐름 | 로그 분석 → 필요시 소스 분석 → JSON 검증·응답 | 동일한 흐름 뒤 그래프 병행 관찰 |
| 그래프에서 모델 문맥 선택 | 없음 | 아직 없음 |
| 근거 추적 | 기존 JSON의 EV·SC·가설 참조 | JSON + 단계·시도 관계 RDF 및 SHACL 보고서 |
| 그래프 추가 모델 호출 | 없음 | 0회 |
| 그래프 작업자 메모리 | 없음 | 프로세스당 약 56MiB, 로컬 표본 |
| 그래프 처리 시간 | 해당 없음 | 재사용 시 중앙값 약 55–59ms, 첫 초기화 약 400ms |
| 로컬 응답 추가 지연 | 기준 | 기존 off/shadow 재생 측정에서 약 3.24ms |

비용 수치는 앞선 [성능 개선 보고서](KNOWLEDGE_GRAPH_PERFORMANCE_2026-10-03.md)의 측정값입니다. 그 HTTP 비교 기준은 현재 코드의 `off`이며, 이번의 이전 커밋 20건 비교에서 얻은 응답 시간 수치로 바꾸어 설명하지 않습니다. 실제 LLM 대기 시간과 운영 동시 부하는 해당 응답 측정에 포함하지 않았습니다.

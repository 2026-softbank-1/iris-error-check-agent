## 검증 대상

기준 코드 `40d39767fcd209c24e84dd88aebeb9979d0a6e9b`에 RDF/SHACL 관찰 경로를 추가했습니다. 외부 백엔드 입력·v3 응답·모델 프롬프트·근거 선택은 유지합니다. 구현·실행 방법은 [개발 문서](KNOWLEDGE_GRAPH_SHADOW.md)에 정리했습니다.

이번 검증에서는 실제 모델과 실제 S3를 호출하지 않았습니다. 기존 테스트 런타임의 응답과 합성 소스 아카이브를 사용했고, RDF 생성·SHACL 검증·별도 프로세스·파일 저장은 실제 구현을 실행했습니다. 아래 수치는 실제 장애 진단 정확도나 LLM 성능의 증거가 아닙니다.

## 로컬 비용 측정

환경: macOS 26.4 / arm64, Python 3.12.14, RDFLib 7.6.0, pySHACL 0.31.0. 다른 테스트·Docker 빌드가 끝난 뒤 예제별 10회씩 순차 실행했습니다. 매번 새 Python 자식 프로세스를 시작하고 새로운 진단 ID를 사용했습니다.

작은 예제는 합성 설정 오류의 공개 v3 결과를 재생했습니다. 확대 예제는 동일 결과에 합성 로그 근거를 추가해 300개로 늘린 부하 측정용 입력입니다. 새 원인·가설을 평가하지 않았습니다. 두 예제 모두 공개 응답에서 재생했으므로 **최종 소스 분석 한 단계만 포함**합니다. 온라인에서 두 분석 단계를 모두 보관할 때의 비용과 같다고 볼 수 없습니다.

| 지표 | 작은 예제 | 근거 300개 예제 |
|---|---:|---:|
| 최종 그래프 트리플 | 110 | 2,792 |
| 저장 성공 / SHACL 통과 | 10/10, 10/10 | 10/10, 10/10 |
| 추가 경과 시간 p50 | 489 ms | 788 ms |
| 추가 경과 시간 p95 | 526 ms | 981 ms |
| 자식 프로세스 CPU p50 | 444 ms | 724 ms |
| 자식 프로세스 최대 RSS p50 | 55.5 MiB | 61.0 MiB |
| 작업별 전체 파일 크기 p50 | 6,995 bytes | 17,139 bytes |

추가 경과 시간은 레코드 구성, 프로세스 시작, 라이브러리 import, 생성·검증·직렬화·파일 저장을 포함합니다. CPU와 RSS는 직렬화 뒤·파일 쓰기 전에 측정한 프로세스 전체 수치입니다. Windows에서는 RSS 수집만 `null`로 기록합니다. Windows 실행 자체는 이번에 검증하지 않았습니다.

백그라운드 부하가 있던 초기 반복 측정은 위 표에서 제외했습니다. 샘플 수가 작고 사례가 한 종류이므로 p95와 메모리는 대략적인 개발 환경 비용으로 사용해야 합니다. API 부모 프로세스의 메모리 증분, 동시 부하, 장시간 보관, 10,000 트리플 근처 입력은 이번 측정에 포함하지 않았습니다.

python evaluation/benchmark_knowledge.py --input results/case-001.json --output-dir results/new-benchmark --runs 10

`iris-error-check-agent:ontology-shadow` 이미지를 실제로 빌드하고 패키지 설치·`pip check`를 통과했습니다. Linux arm64 컨테이너에서 외부 네트워크 없이 저장된 예제를 관찰 프로세스로 전달했습니다.

- 실행 사용자 UID 10001에서 온톨로지·SHACL 리소스 사용 및 그래프 저장 성공
- 최종 SHACL 통과, 타깃 커버리지 1.0, 산출물 6개 생성
- 새 작업 디렉터리 0700, 파일 0600 권한 확인

Docker 값은 첫 실행 1회 결과이며 반복 성능 평가가 아닙니다. 로컬 macOS 측정과 직접 비교하지 않습니다. 실제 모델 호출·OpenCode 진단 전체 흐름을 컨테이너에서 다시 실행하지는 않았습니다.

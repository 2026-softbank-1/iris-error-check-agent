## 평가 목적과 범위

원인 정답이 있는 합성 입력을 기존 `POST /diagnose`에 전달하여 실제 LLM 진단의 기준 성능을 측정합니다. 입력은 기존 백엔드 `success/message/data` 규격이며, 공개 응답과 운영 코드·프롬프트는 변경하지 않습니다. S3 전송은 메모리 아카이브와 `httpx.MockTransport`로 대신하고 모델은 실제로 호출합니다.

현재 그래프는 `shadow` 관찰 기능입니다. 모델의 근거 선택이나 판단에 개입하지 않으므로 이 평가는 **현재 Agent의 합성 장애 성능**이며, 그래프 적용에 따른 진단 정확도 향상을 비교한 A/B 실험은 아닙니다.

|---|---|

| 코드 위치 적중률 | 소스 4건의 정답 줄을 finding과 인용 SC에 포함하고 최상위 가설에 연결 |

실행 실패는 시도한 사례의 상태·원인 점수에서 오답으로 셉니다. 미실행 사례는 정답 또는 오답으로 채워 넣지 않으며 전체 평가 완료 비율을 함께 기록합니다. 정상 오탐·정보 부족 단정 지표를 읽을 때에도 실행 오류 수를 함께 확인해야 합니다.

## 재현과 산출물

저장소 루트의 Python 가상환경에서 실행합니다. 기존 제공자·모델 설정을 사용하며 이 실행기의 `--env-file`이 프로세스 환경변수보다 우선합니다. 자동 재시도와 모델 기반 채점은 없습니다. **실행 시 실제 모델 사용량이 발생합니다.**

```bash
.venv/bin/python evaluation/run_synthetic_accuracy.py --env-file .env --output-dir results/synthetic-new --knowledge-mode shadow
```

모델 호출 전에 백엔드 입력·정답·로그의 프로젝트 상대 경로·실제 압축 파일 로더의 파일 접근을 검사합니다. 인증·한도·모델 설정·연결·시간 초과 오류가 발생하면 결과를 저장하고 다음 사례 호출을 중단합니다.

산출물은 다음을 포함합니다.

- `dataset-frozen.json`: 해당 실행의 데이터·정답 스냅샷
- 사례별 JSON: 실제 공개 API 응답
- `summary.json`: 분모가 있는 점수, 상태 혼동 행렬, 실행 오류, 모델 호출·토큰, 시간, 그래프 관찰
- `knowledge/`: 실제 RDF·SHACL·관찰 스냅샷

데이터를 다시 만들려면 `evaluation/build_synthetic_incidents.py`를 실행합니다. Python의 예외 문구는 버전에 따라 달라질 수 있으므로 새로 만든 데이터는 새로운 평가 자료로 취급하고 데이터 SHA-256을 확인합니다.

## 해석과 다음 평가

각 사례는 유효한 입력에서 실제 모델을 한 번씩 평가합니다. 작은 표본과 단순한 단일 원인, 사례 제작·채점의 공통 주체 때문에 운영 환경으로 점수를 일반화할 수 없습니다. Wilson 95% 구간은 표본 수에 따른 참고 수치이며, 가상 사례가 운영 장애의 무작위 표본임을 뜻하지 않습니다.

실제 운영 장애 정확도를 측정하려면 별도로 수집한 장애에 담당자가 확인한 원인·수정·복구 결과를 붙이고 같은 채점 절차로 평가해야 합니다. 그래프를 판단에 사용하는 `assist`를 도입할 때는 같은 장애 자료의 기존 방식과 `assist`를 비교하고, 원인 식별·오탐·단정·모델 비용·시간을 함께 측정합니다.
